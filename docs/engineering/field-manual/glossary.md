# Engineering Glossary: Definitions and NUTS Usage

This is the quick lookup for terms used across the NUTS docs. The **NUTS usage** column distinguishes current implementation from proposed work. Follow the links for the full explanation and source paths.

| Term | Definition | NUTS usage | Further reading |
|---|---|---|---|
| At-least-once delivery | A message may be delivered again when a sender or consumer cannot know whether a prior attempt completed. | The selected outbox and RabbitMQ paths can redeliver; consumers use event/business keys for deduplication. | [Notifications domain](../../domains/notifications-and-async-delivery.md) · [Part IV](04-messaging-and-rabbitmq.md) |
| Backpressure | A producer slows or bounds work when a downstream consumer cannot keep up. | Product-view flushes are capped per invocation, but the Redis list has no explicit application-level length cap; sustained capacity, buffer bounds, and backlog alerts need measurement and scale work. | [Analytics domain](../../domains/analytics-and-measurement.md) · [Part IV](04-messaging-and-rabbitmq.md) |
| Candidate generation | Selecting a bounded set of items that may be relevant before final scoring. | Current recommendations are deterministic application logic; a separate learned candidate generator is proposed, not implemented. | [Part VII](07-discovery-analytics-recommendations.md) |
| Cold start | A user or item has too little history for personalized ranking. | Anonymous cold-start marketplace discovery is separate from personalized recommendations. | [Part VII](07-discovery-analytics-recommendations.md) |
| Connection pool | A reusable set of database connections shared by application requests. | Prisma `pg` pools are per API process; connection demand rises with replica count and must fit the database budget. | [Platform Runtime and Data](../../platform/runtime-and-data.md) · [Performance](../../performance/README.md) |
| Cursor/keyset pagination | Continuation based on the last ordered key rather than an offset from the beginning. | `/api/v1/discover` uses a cursor containing the active sort value and product ID for deterministic continuation. | [Discovery domain](../../domains/discovery-and-personalization.md) · [Part I](01-networking-and-web-api.md) |
| CSRF | Cross-site request forgery: a browser is induced to send an authenticated state-changing request from another site. | Cookie-authenticated writes use a CSRF cookie/header pair; review the deployed origin and proxy policy with the auth flow. | [Identity domain](../../domains/identity-and-account-security.md) · [Part V](05-application-security.md) |
| Dead-letter queue (DLQ) | A destination for messages that a consumer cannot process normally. | RabbitMQ consumer failures route to a shared durable DLQ; automatic delayed retry and operator replay are not implemented as a complete workflow. | [Notifications domain](../../domains/notifications-and-async-delivery.md) · [Part IV](04-messaging-and-rabbitmq.md) |
| Embedding | A learned numeric representation used to compare semantic similarity. | Not currently used for product ranking; it is an option to evaluate only if content similarity has a measured need. | [Part VII](07-discovery-analytics-recommendations.md) · [Recommendation scaling plan](../../scaling/recommendations.md) |
| Event attribution | A rule that connects an earlier action or exposure to a later outcome. | Analytics defines identity and time windows for view/cart/purchase cohorts; anonymous identities are not merged into a customer identity at sign-in. | [Analytics domain](../../domains/analytics-and-measurement.md) |
| Event retention | A policy for how long raw or derived event records remain available. | Product-view/marketplace-action and recommendation-event data have different configured retention windows; verify the analytics guide before relying on a historical range. | [Analytics domain](../../domains/analytics-and-measurement.md) |
| Feature store | Infrastructure for consistent model features across offline training and online serving. | Not operated by NUTS; consider only after model evaluation justifies its cost. | [Part VII](07-discovery-analytics-recommendations.md) |
| Idempotency | Repeating the same logical operation produces one intended business effect. | Order creation, provider event handling, refund references, and selected ledger writes use idempotency/deduplication mechanisms; guarantees vary by flow. | [Shopping domain](../../domains/shopping-promotions-and-orders.md) · [Payments domain](../../domains/payments-and-financial-ledger.md) |
| Implicit feedback | Behavior that suggests interest without an explicit rating. | Views, searches, cart/wishlist actions, purchases, follows, and recommendation interactions feed current deterministic recommendations where available. | [Part VII](07-discovery-analytics-recommendations.md) |
| Inference fallback | A safe behavior used when model scoring is too slow or unavailable. | The deterministic ranker is the proposed fallback for any future ML ranker; no model-serving path exists today. | [Recommendation scaling plan](../../scaling/recommendations.md) |
| Modular monolith | One deployable application organized into internal modules with explicit responsibilities. | NUTS API modules share one NestJS process and infrastructure; they are not independently deployed services. | [Platform Runtime and Data](../../platform/runtime-and-data.md) · [Part I](01-networking-and-web-api.md) |
| Offline/online evaluation | Offline evaluation uses historical data; online evaluation measures outcomes with live controlled variants. | These are proposed prerequisites for a trained recommendation ranker; NUTS currently has no claimed recommendation experiment result. | [Part VII](07-discovery-analytics-recommendations.md) · [Recommendation scaling plan](../../scaling/recommendations.md) |
| Outbox pattern | Persisting an event record in the same database transaction as the business change, then publishing it asynchronously. | Selected payment, refund, order-status, and vendor-follow changes use the outbox; it does not cover every business write. | [Notifications domain](../../domains/notifications-and-async-delivery.md) · [Part IV](04-messaging-and-rabbitmq.md) |
| Re-ranking | Applying final constraints or diversity rules after initial candidate scoring. | Business-rule re-ranking is proposed for future ML scoring; current logic remains deterministic. | [Part VII](07-discovery-analytics-recommendations.md) |
| Server-Sent Events (SSE) | A one-way server-to-browser stream over an HTTP connection. | Notification updates use SSE; analytics dashboards currently poll. | [Notifications domain](../../domains/notifications-and-async-delivery.md) · [Part I](01-networking-and-web-api.md) |
| System of record | The authoritative store for a category of business data. | PostgreSQL is authoritative for commerce state; Redis and RabbitMQ support cache, coordination, buffering, and async delivery. | [Platform Runtime and Data](../../platform/runtime-and-data.md) |
| Transaction | An atomic group of database operations that commit or roll back together. | Commerce changes use PostgreSQL transactions; selected flows include their outbox row in the same transaction. | [Payments domain](../../domains/payments-and-financial-ledger.md) · [Part II](02-databases-and-concurrency.md) |
| Transactional outbox | The outbox pattern combined with a database transaction, avoiding a split commit between business state and message intent. | Used for selected events, with at-least-once relay delivery and consumer deduplication. | [Notifications domain](../../domains/notifications-and-async-delivery.md) · [Part IV](04-messaging-and-rabbitmq.md) |
| CQRS / event sourcing | CQRS separates command and query models; event sourcing stores the event log as the source of truth. | NUTS does not implement system-wide CQRS or event sourcing. | [Platform Runtime and Data](../../platform/runtime-and-data.md) · [Part II](02-databases-and-concurrency.md) |
